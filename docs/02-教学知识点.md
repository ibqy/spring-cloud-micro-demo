# 教学知识点

本项目通过"用户-订单"业务场景串联微服务核心概念。本文按知识点逐条展开，每个知识点都对应仓库中可直接阅读的代码。

## 架构总览

```
                         ┌─────────────────┐
                         │   Gateway :8080  │  ← 外部请求统一入口
                         └────────┬────────┘
                    ┌────────────┼────────────┐
                    ▼                         ▼
          ┌─────────────────┐     ┌─────────────────┐
          │  user-service   │     │  order-service  │
          │    :8081        │     │    :8082        │
          │                 │◄────│ OpenFeign 调用   │
          │  用户 CRUD      │     │  订单 CRUD       │
          └─────────────────┘     └─────────────────┘
```

| 模块 | 技术栈 | 端口 | 核心功能 |
|------|--------|------|----------|
| `common` | Spring Boot 3.4.x | — | 公共 DTO、API 接口定义 |
| `user-service` | Spring Boot 3.4.x | 8081 | 用户 CRUD，提供 REST API |
| `order-service` | Spring Boot 3.4.x + OpenFeign | 8082 | 订单 CRUD，OpenFeign 调用用户服务 |
| `gateway-service` | Spring Cloud Gateway | 8080 | 统一入口、路由转发、过滤器、限流 |

## 知识点详解

### 01 · Spring Cloud Gateway 路由配置

网关是微服务的统一入口：外部请求不再直连业务服务，而是先到 Gateway，由路由规则转发到对应下游。重点看路由的匹配条件（路径断言）与目标 URI 的配置方式。

代码位置：[gateway-service/src/main/resources/application.yml](https://github.com/ibqy/spring-cloud-micro-demo/blob/main/gateway-service/src/main/resources/application.yml)

### 02 · Gateway 过滤器（Header 注入）

过滤器是网关的核心扩展点。本示例演示在转发前后修改请求——例如注入自定义 Header 传递调用来源信息，这是灰度发布、链路追踪的基础手法。

代码位置：[gateway-service/src/main/java/com/xb/cloud/gateway/config/GatewayConfig.java](https://github.com/ibqy/spring-cloud-micro-demo/blob/main/gateway-service/src/main/java/com/xb/cloud/gateway/config/GatewayConfig.java)

### 03 · OpenFeign 声明式 HTTP 客户端

写一个 Java 接口加注解，就像调用本地方法一样调用远程服务，HTTP 细节全部由框架处理。对比手写 RestTemplate/WebClient，理解声明式调用带来的可维护性提升。

代码位置：[order-service/src/main/java/com/xb/cloud/order/client/UserFeignClient.java](https://github.com/ibqy/spring-cloud-micro-demo/blob/main/order-service/src/main/java/com/xb/cloud/order/client/UserFeignClient.java)

### 04 · 服务间调用 + 异常处理

下游服务不可用、超时、返回错误码时上游怎么应对？订单服务调用用户服务是典型的跨服务依赖，这里演示了调用失败时的异常处理策略。

代码位置：[order-service/src/main/java/com/xb/cloud/order/controller/OrderController.java](https://github.com/ibqy/spring-cloud-micro-demo/blob/main/order-service/src/main/java/com/xb/cloud/order/controller/OrderController.java)

### 05 · 公共模块契约（DTO + API 接口）

把 DTO 和 API 接口定义抽到 `common` 模块，让服务提供方与消费方共享同一份契约，避免两边字段不一致导致的隐式 bug。这是微服务接口治理的第一步。

代码位置：[common/src/main/java/com/xb/cloud/common/api/UserApi.java](https://github.com/ibqy/spring-cloud-micro-demo/blob/main/common/src/main/java/com/xb/cloud/common/api/UserApi.java)

### 06 · 统一响应体 Result

所有接口返回统一结构的 `Result<T>`（code / message / data），让前端与调用方可以用同一套方式判断成败，也为网关层的统一错误处理提供基础。

代码位置：[common/src/main/java/com/xb/cloud/common/dto/Result.java](https://github.com/ibqy/spring-cloud-micro-demo/blob/main/common/src/main/java/com/xb/cloud/common/dto/Result.java)

### 07 · IP 限流 KeyResolver

网关层限流保护下游服务。示例基于请求者 IP 作为限流 key，配合 Gateway 的 RequestRateLimiter 过滤器实现——生产中可换成用户 ID 或 API Key 维度。

代码位置：[gateway-service/src/main/java/com/xb/cloud/gateway/config/GatewayConfig.java](https://github.com/ibqy/spring-cloud-micro-demo/blob/main/gateway-service/src/main/java/com/xb/cloud/gateway/config/GatewayConfig.java)

### 08 · Resilience4j 熔断器

微服务调用中，下游不可用会导致上游线程耗尽（雪崩效应）。熔断器在错误率达到阈值时快速失败，不再等待超时。本示例为 OpenFeign 调用加上 `@CircuitBreaker` 保护。

代码位置：[order-service/src/main/java/com/xb/cloud/order/client/UserFeignClient.java](https://github.com/ibqy/spring-cloud-micro-demo/blob/main/order-service/src/main/java/com/xb/cloud/order/client/UserFeignClient.java)

### 09 · Fallback 降级处理

熔断器打开或调用失败时，`UserFallbackHandler` 自动返回降级响应，避免异常直接抛给前端。区分三种触发场景：熔断器打开（`CallNotPermittedException`）、超时异常、网络异常。

代码位置：[order-service/src/main/java/com/xb/cloud/order/fallback/UserFallbackHandler.java](https://github.com/ibqy/spring-cloud-micro-demo/blob/main/order-service/src/main/java/com/xb/cloud/order/fallback/UserFallbackHandler.java)

### 10 · 熔断器配置（滑动窗口/阈值/半开）

```yaml
resilience4j:
  circuitbreaker:
    instances:
      userService:
        sliding-window-type: COUNT_BASED       # 基于调用次数的滑动窗口
        sliding-window-size: 10                # 最近 10 次调用
        failure-rate-threshold: 50             # 失败率 ≥ 50% 触发熔断
        wait-duration-in-open-state: 10s       # OPEN 持续 10 秒后进入 HALF_OPEN
        permitted-number-of-calls-in-half-open-state: 3  # 探测放行 3 个
        slow-call-duration-threshold: 2s       # 响应 > 2 秒视为慢调用
        slow-call-rate-threshold: 80           # 慢调用占比 ≥ 80% 也触发
```

代码位置：[order-service/src/main/resources/application.yml](https://github.com/ibqy/spring-cloud-micro-demo/blob/main/order-service/src/main/resources/application.yml)

### 11 · 全局异常处理

`GlobalExceptionHandler` 放在 `common` 模块，user-service 和 order-service 自动继承。处理参数校验异常、缺少参数异常和未知异常，统一返回 `Result<T>` 格式。

代码位置：[common/src/main/java/com/xb/cloud/common/exception/GlobalExceptionHandler.java](https://github.com/ibqy/spring-cloud-micro-demo/blob/main/common/src/main/java/com/xb/cloud/common/exception/GlobalExceptionHandler.java)

## 诚实边界：本项目覆盖与未覆盖的内容

| 组件 | 状态 | 说明 |
|------|------|------|
| Gateway 网关 | ✅ 已实现 | 路由、过滤器、IP 限流 |
| OpenFeign 服务调用 | ✅ 已实现 | order → user 的声明式调用 |
| 熔断降级 | ✅ 已实现 | Resilience4j @CircuitBreaker + UserFallbackHandler 降级处理 |
| 负载均衡 | ❌ 未实现 | 单实例部署下没有多节点可负载；进阶可接入 Spring Cloud LoadBalancer + 多实例注册 |

同样**未涉及**的内容：注册中心（Nacos / Eureka）、配置中心、分布式事务、链路追踪、容器化部署。这些是微服务进阶学习的方向，建议在本项目跑通后再逐个引入。

## 启动与验证

前置：JDK 21+、Maven 3.9+。

```bash
# 1. 编译全部模块
mvn clean compile

# 2. 三个终端分别运行
mvn -pl user-service spring-boot:run      # 用户服务 8081
mvn -pl order-service spring-boot:run     # 订单服务 8082
mvn -pl gateway-service spring-boot:run   # 网关 8080
```

验证完整调用链路：

```bash
# 1. 通过网关查询用户（Gateway → user-service）
curl http://localhost:8080/api/users/1

# 2. 创建订单（Gateway → order-service → OpenFeign → user-service）
curl -X POST http://localhost:8080/api/orders \
  -H "Content-Type: application/json" \
  -d '{"userId":1,"productName":"iPad","amount":3999}'

# 3. 直接查订单
curl http://localhost:8080/api/orders/1
```
